# StormOps v2.0.0

StormOps v2.0.0 establishes a secure-by-default chaos engineering laboratory with durable execution controls and automated proof of pod recovery. The API and demo service are both versioned 2.0.0 and target Java 21; CI verifies JDK 21 and 25.

## Changes

- Authentication is enabled by default. Missing credentials prevent startup; disabling authentication requires the explicit dev profile and an explicit opt-out.
- Experiment requests default to dry-run. A persistent kill switch starts engaged.
- PostgreSQL admission reserves one experiment across API instances sharing the database. Intent is audited before injection; completion, audit and reservation release commit atomically.
- The fixed blast radius permits one pod in the dedicated stormops-lab namespace, selected by app=stormops-demo. Pod UID preconditions prevent deleting a replacement with a reused name.
- Pre/post steady-state checks require healthy replicas, a successful baseline and fresh Prometheus evidence. Timeouts, error-rate checks and stop requests prevent further injection and latch safety controls when an outcome is uncertain.
- A dedicated stormops-runner ServiceAccount and namespaced Role replace reliance on an administrator identity in the tested setup.
- A disposable kind end-to-end test verifies actual ServiceAccount permissions, one real pod replacement, recovery, durable audit, persistence after API restart and kill-switch enforcement.
- CI builds runtime images and gates GHCR publication and GitHub release creation on the complete test suite.
- MIT licensing is included. Copyright (c) 2026 Samuel Texa.

## Upgrade requirements

Configure database and distinct admin/viewer credentials before starting the API. Flyway V2 adds safety-control and audit tables without deleting existing experiment history; back up the database before upgrading.

Provision a dedicated runner kubeconfig using the supplied Role and ServiceAccount. Set STORMOPS_KUBECONFIG to its protected file if the default path is unsuitable. The existing local laboratory's credentials are not migrated automatically.

Supply fresh Prometheus evidence and baseline traffic, inspect the initial stop state, and run a dry-run before explicitly resuming live experiments. Existing clients that omit dryRun now perform a dry-run; live injection requires dryRun=false and the appropriate confirmation header.

## Operational boundaries

This release is for an isolated local laboratory. It does not deploy or enable experiments automatically. The existing frontend remains unchanged and has no new live-execution or safety controls; use the documented operator API.

Pod deletion cannot be undone. Kubernetes performs replacement; interrupted or uncertain runs remain blocked until an operator completes the documented offline recovery review. Stop and timeout checks are cooperative and cannot retract a request already sent.

Runtime images use Java 21 and run without root privileges. The API retains loopback defaults and requires explicitly configured networking and mounted runner credentials. The release pipeline builds Linux amd64 images; multi-architecture publication is not claimed.
